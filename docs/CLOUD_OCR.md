# 云端教材解析（2.2.0）

## 模型选择

默认 `qwen3.5-ocr`，通过现有 DashScope 账户调用 OpenAI 兼容 Chat API，一次处理一页图片。它专门面向文档、表格和文字提取，比通用视觉问答更直接匹配 OCR 任务。

- [Qwen OCR 官方文档](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr)
- [模型参数与地域](https://help.aliyun.com/zh/model-studio/qwen3-5-ocr)
- [API 参考](https://help.aliyun.com/zh/model-studio/qwen-vl-ocr-api-reference)

官方还支持 Responses API 直接解析 PDF，但有文件大小和页数限制。本程序采用逐页图片路径，保留原始物理页码，适合大教材断点恢复，不把整本教材作为一次请求上传。
旧默认别名 `qwen-vl-ocr` 自动映射到新模型，其他显式模型名保留；没有权限时明确报错，不悄悄切换供应商或调用本地 AI。

## 处理规则

1. 普通文字 PDF 直接使用 PyMuPDF；扫描／低质量文字页和识别出的双栏页使用云端 OCR。自动检测是启发式规则，复杂图文排版可手动勾选强制 OCR。
2. 云端每次 90 秒超时，429、5xx 或连接失败最多重试一次；认证／模型权限错误不重试。SDK 自动重试关闭，避免重叠计费。
3. 拒绝空响应、截断和过滤结果。逐页暂存成功正文与元数据，然后分批向量化；全部完成才事务性替换原索引。已提交页／向量不重复调用，云端完成但本地提交前中断的最后一次请求仍可能重复收费。
4. 保留表格和数学文本；对文本用 LaTeX 包裹、TSV 表格和数字页码做保守适配，不改写医学内容。复杂表格合并单元格、公式等仍需人工核对。
5. 页面 OCR trace（实际模型、请求 ID、usage、耗时、结束原因）保存在分块元数据中，不保存密钥。

批量信息识别与印刷页码校准对扫描页最多抽样 60 页，页眉／页脚分别请求；这不是全文索引，也不保证整本页码自动映射。不足以确认时使用物理页或手工校准，不猜测页码。重复启动校准可能重复收费。

## 索引与部署

解析来源和新建索引指纹更新，但检索兼容性检查基于供应商、地址、向量模型、维度及索引算法，并验证存储指纹。旧 Docling 索引不被改写、删除或自动重建。

安装包不含 Docling、RapidOCR、ONNX Runtime、Torch、Transformers 和模型权重。升级仅清理安装目录下明确列出的旧 AI 资源，保留业务数据库、教材和旧发布包。离线环境可浏览／审核现有数据、提取普通文字，但无法完成云 OCR 或向量化。

无 GPU 的 Linux 服务器可使用 Python CLI；当前安装器仍只适用于 Windows。共享节点需限制应用并发，不能仅因机器有 40 核就占满全部核心。本次不承诺未经实测的 Linux 桌面部署。

## 验证边界

真实账户已验证合成中文与数值页，以及表格、双栏、数字页码三个案例；后者数值／术语存在性检查均通过，双栏阅读顺序通过。三个案例合计 6127 token，单次响应约 0.42～2.14 秒；这是小样本接口测试，不是整本教材吞吐量或 OCR 准确率基准，也不证明优于 Docling。
安装验收使用离线模拟云客户端，不读取真实教材、不自动消费 API。人工审核仍是医学内容的最终质量把关环节。
